IMPORTANT SWAGGER AUTHORIZATION INSTRUCTIONS
--------------------------------------------

1. Call POST /api/v1/auth/login with one of the accounts below.
2. Copy only the value of accessToken from the response.
3. Click Authorize at the top of Swagger.
4. Paste the token value. Do not add quotation marks.
5. Login as a different role and replace the authorized token whenever the
   instructions switch actors.

JWTs expire, so permanent tokens are intentionally not stored in this file.
Generate a fresh token from the login endpoint before each demonstration.

RUN A NEW LIVE END-TO-END DEMO
==============================

The permanent users, provider, area, profiles, and wallets are reused.
For every new live run, copy the new request, offer, assignment, snapshot, and
transfer IDs returned by Swagger.


STEP 1 — ADMIN FUNDS THE COORDINATOR WALLET
-------------------------------------------

Login as ADMIN.

POST /api/v1/wallets/8a6e1ecb-9715-4484-9ddc-fff8b7d20e9f/fund

Body:

  {
    "amount": 50000
  }

Expected:
  201 Created


STEP 2 — AGENT REPORTS THE LOW-CASH SNAPSHOT
--------------------------------------------

Login as AGENT.

POST /api/v1/balance-snapshots

Body:

  {
    "agentId": "7eb9de31-21b1-4a8e-bada-b18718f4156e",
    "cashBalance": 5000,
    "eMoneyBalance": 100000,
    "recordedAt": "2026-07-30T11:00:00.000Z"
  }

Copy the returned id as NEW_BEFORE_SNAPSHOT_ID.


STEP 3 — AGENT REQUESTS PHYSICAL CASH
-------------------------------------

Remain logged in as AGENT.

POST /api/v1/liquidity-requests

Body:

  {
    "requesterId": "7eb9de31-21b1-4a8e-bada-b18718f4156e",
    "requesterType": "AGENT",
    "liquidityType": "PHYSICAL_CASH",
    "providerId": "7ca782b3-abc0-486d-a4c7-3bfd96bc4f3f",
    "areaId": "9562f349-b010-4f5c-b888-8714fd148c76",
    "amount": 50000,
    "urgency": "HIGH",
    "allowPartial": false,
    "expiresAt": "2027-12-31T23:59:59.000Z",
    "notes": "Physical cash required for customer withdrawals"
  }

Copy the returned id as NEW_REQUEST_ID.


STEP 4 — COORDINATOR FINDS THE OPEN REQUEST
-------------------------------------------

Login as COORDINATOR.

GET /api/v1/liquidity-requests?providerId=7ca782b3-abc0-486d-a4c7-3bfd96bc4f3f&status=open

Find NEW_REQUEST_ID in the response.


STEP 5 — COORDINATOR OFFERS TO FULFIL THE REQUEST
-------------------------------------------------

Remain logged in as COORDINATOR.

POST /api/v1/liquidity-offers

Replace NEW_REQUEST_ID:

  {
    "requestId": "NEW_REQUEST_ID",
    "coordinatorId": "65596142-d0ce-49b4-9f0a-2f888f5d20f0",
    "availableAmount": 50000,
    "etaMinutes": 20,
    "note": "Can deliver physical cash within twenty minutes"
  }

Copy the returned id as NEW_OFFER_ID.


STEP 6 — AGENT ACCEPTS THE OFFER
--------------------------------

Login as AGENT.

POST /api/v1/liquidity-offers/NEW_OFFER_ID/accept

Body:

  {
    "assignedAmount": 50000
  }

Copy the returned id as NEW_ASSIGNMENT_ID.


STEP 7 — COORDINATOR COMPLETES THE TRANSFER
-------------------------------------------

Login as COORDINATOR.

POST /api/v1/liquidity-transfers

Required header:
  Idempotency-Key: demo-live-transfer-002

IMPORTANT:
  Use a new unique Idempotency-Key for each separate live demo.

Replace NEW_REQUEST_ID and NEW_ASSIGNMENT_ID:

  {
    "fromWalletId": "8a6e1ecb-9715-4484-9ddc-fff8b7d20e9f",
    "toWalletId": "531f1e4a-326d-4c31-8bb5-d41fbe23e4bc",
    "amount": 50000,
    "transferType": "COORDINATOR_SUPPLY",
    "requestId": "NEW_REQUEST_ID",
    "assignmentId": "NEW_ASSIGNMENT_ID"
  }

Expected:
  201 Created
  status = "success"

Copy the returned id as NEW_TRANSFER_ID.


STEP 8 — AGENT REPORTS THE AFTER-TRANSFER SNAPSHOT
--------------------------------------------------

Login as AGENT.

POST /api/v1/balance-snapshots

The permanent agent wallet already contained 50000 from the seeded flow.
After one additional live transfer, its wallet balance is 100000.

  {
    "agentId": "7eb9de31-21b1-4a8e-bada-b18718f4156e",
    "cashBalance": 100000,
    "eMoneyBalance": 100000,
    "recordedAt": "2026-07-30T11:30:00.000Z"
  }

Copy the returned id as NEW_AFTER_SNAPSHOT_ID.


STEP 9 — ADMIN REVIEWS THE RESULT
---------------------------------

Login as ADMIN.

List transfers:
  GET /api/v1/liquidity-transfers

Read the new transfer:
  GET /api/v1/liquidity-transfers/NEW_TRANSFER_ID

List snapshots:
  GET /api/v1/balance-snapshots

Read the request:
  GET /api/v1/liquidity-requests/NEW_REQUEST_ID

Read the agent wallet:
  GET /api/v1/wallets/531f1e4a-326d-4c31-8bb5-d41fbe23e4bc

Read the coordinator wallet:
  GET /api/v1/wallets/8a6e1ecb-9715-4484-9ddc-fff8b7d20e9f

Expected after one additional live run:
  New request status:          fulfilled
  Agent wallet balance:       100000
  Coordinator wallet balance: 0
